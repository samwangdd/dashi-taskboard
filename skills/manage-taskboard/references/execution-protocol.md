# Execution protocol 1

Read `issue get`, full comments and attachments for semantic permission. Then read `issue eligibility ID --project PROJECT --json`; require `protocol=1`, `eligible=true`, and save task `version`, `policyVersion` and effective policy. Historical `threadBinding` / `agentSession` is provenance. Only `executionState.active` is execution occupancy. Cloud native owners use a workspace key; the companion's local `executionWorkspace` resolution is separate, and a missing mapping stays unresolved. Jira-synchronized sources explicitly refuse this execution lifecycle.

Claim with `issue claim ID --project PROJECT --if-version N --policy-version N --request-id UNIQUE_ID` and the real owner identity. External platforms use `--agent-platform claude|pi|agy|grok --session-id ID`. Codex uses `--thread-id "$CODEX_THREAD_ID"` plus all five matching `--binding-*` fields. Read back `executionState.active.id`, owner, `startedAt` and `progressAt` before implementation. Reuse the same request ID only for uncertain retries of that claim.

Resume only your exact active owner and claim ID: `issue resume ID --claim-id CLAIM --if-version N ...identity`. Keep the claim across scheduler ticks. Task field edits use `issue update` / `issue move` with `--claim-id CLAIM` and the same owner. End ownership explicitly with `issue release ID --claim-id CLAIM --status todo|in_review|blocked|done|canceled --if-version N ...identity`, then read back no active claim and the preserved history entry. Workflow acceptance still controls `done`.

A conflict refreshes task, comments and eligibility; it never authorizes takeover. `todo` with only historical session metadata can be claimed when authority says eligible. Another active owner, legacy `in_progress` with no claim, unknown executor, or missing initial progress time stays protected. Age and process invisibility never release occupancy. Explicitly authorized legacy recovery may return a stopped task to `todo` while preserving provenance. New active claims recover by resuming the original real owner; an unavailable owner requires explicit operator recovery, not impersonation.

`issue execution-preview --project PROJECT --json` is read-only. Project policy is read by `project execution-policy get PROJECT`; changing it requires explicit project scope and a versioned `set` with `--policy-file`. Selectors compare effective policy to their approved config and consume authoritative eligibility; they keep only ordering, repository concurrency and semantic checks locally.

When the CLI/server lacks this protocol or returns an unsupported/invalid snapshot, remain report-only and report the required upgrade. Keep the configured CLI and endpoint. Old `issue move --status in_progress` is not a fallback. Do not install, restart, run a schedule, or migrate real task ownership merely to test the protocol.
